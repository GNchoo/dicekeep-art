# 기본 주사위 재질 통일

기존 육면체는 낡은 상아색 석재 이미지와 짙은 붉은 눈을 사용하지만, 나머지 주사위는 단색 도형으로 그려져 서로 다른 재질처럼 보였다. 육면체 원본을 기준으로 번호 없는 공통 석재 이미지를 제작하고 다른 주사위의 실제 3D 표면에 입힌다.

기본 주사위 세트는 외눈 구슬(d1), 사면체(d4), 육면체(d6), 팔면체(d8), 십이면체(d12), 이십면체(d20)와 에픽·신화·태초 이십면체다. 육면체의 기존 여섯 원본은 유지하고 나머지 표면을 같은 따뜻한 상아색, 미세한 균열과 마모, 짙은 붉은 음각 표식으로 맞춘다. 등급 색은 획득 효과와 안내에 사용한다.

완성된 정지 주사위 그림으로 굴림을 덮는 대신, 실제 다면체의 각 면에 이미지와 번호를 함께 매핑한다. 기본형의 재질 설정은 추후 스킨 외형을 추가할 수 있도록 주사위의 면 수·보상 성수·확률과 분리한다.

## 생성 원본과 재현

내장 `image_gen`을 **1회** 사용했다. 모든 다면체가 공유하는 재질 한 장을 만들었으며 별도 유료 API나 CLI 생성은 사용하지 않았다. 도구는 금액 정보를 제공하지 않았다.

- [실제 프롬프트](prompt.txt)
- [생성 기록과 원본 해시](generation.json)
- [보관 원본](source.png): 1254×1254 RGB
- [게임용 재질](../../../dice/skins/ivory-worn/material.png): 512×512 RGB

번호 없는 재질은 불투명 타일이며 다면체의 실제 면 경계에서 잘라 그린다. 배경 제거·재색칠은 하지 않았다. 원본을 Lanczos 축소하고 PNG로 무손실 저장한 과정은 다음 명령으로 재현한다.

```sh
node tools/art-review/dice-base-96/rebuild.mjs
```

## 스킨 확장 경계

`content.js`의 `DICE_SKINS`는 기본 ID, 공통 재질 경로, 음각 표식 색, 기존 큐브 면 6장의 경로를 기록한다. 현재 활성 기본형은 `ivory-worn`이다. `INFINITY.chest`의 면 수·등급·확률·보상 규칙과 분리되어 있다.

현재 큐브 렌더러는 기존 여섯 원본을 그대로 사용한다. 향후 큐브 스킨의 선택된 면 세트를 연결하는 작업과 상점 판매·소유권·장착 UI는 후속 기능이다. 이번 작업으로 제공하는 것은 기본 외형 통일과 외형 카탈로그의 시작점이다.

다면체는 번호와 재질을 한 면 텍스처로 만들어 회전시킨다. 구슬도 고정된 표면 좌표로 재질을 매핑한다. 캐시는 최대 두 재질 세트로 제한하며 에픽·신화·태초는 같은 이십면체 세트를 공유한다. 재질을 받지 못한 경우에는 육면체 원본의 눈 사이 상아색 부분을 사용해 기본 톤을 유지한다.

## 확정면과 실제 결과 일치

검수 중 기존 회전 보간 코드의 거의 180도 회전 경로에서 축의 부호가 뒤집히는 오류를 재현했다. 확정된 값과 지급 결과는 7이지만 중앙과 슬롯에는 16면이 보이는 입력이었다. 재질 수정 전 코드에서도 같은 입력으로 동일한 문제가 발생하는 것을 실제 브라우저와 행렬 재생으로 확인했다.

가장 큰 축 성분을 먼저 복원하고 대칭 행렬 성분과 회전 방향으로 나머지 축의 부호를 구하도록 수정했다. 작은 각도와 180도 부근에서도 안정적으로 각도를 읽는다. 면 수·목표 면·확률·보상 값을 바꾸지 않고, 정착한 그림이 이미 정해진 결과를 정확하게 가리키도록 한다.

[수정 전 실제 화면](evidence/rotation-before.png) · [수정 후 실제 화면](evidence/rotation-after.png) · [이전 코드 동일 입력 재생](evidence/rotation-original-replay.json) · [회귀 검사 결과](evidence/rotation-regression.json)

```sh
node tools/dice-rotation-test.cjs
```

이 검사는 실제 게임 함수와 면 기하를 사용한다. 21개 재현 입력 및 20개 목표 면 × 9개 회전축 × 7개 180도 전후 각도의 합계 1,281개에서 정면 숫자와 목표 행렬을 검사한다. 최종 최대 행렬 오차는 약 1.45×10⁻¹⁵이며, 이전 코드에는 재현 입력에서 실제로 실패하는 것도 확인했다.

## 실제 게임 검증

[수정 전 9종](evidence/before-phone.png) · [수정 후 9종](evidence/after-phone.png) · [데스크톱 9종](evidence/after-desktop.png) · [D20의 최종 1~20면](evidence/all-20-results.png)

- [최종 정상 로드](evidence/after.json): 휴대폰 440×956와 데스크톱 1240×860에서 각각 9종의 실제 회전·정착·결과 전달, 고정 자세 픽셀 안정성과 면에 붙은 재질 좌표를 확인했다. D20의 최종 1~20면도 전부 맞는다.
- [재질 로드 실패](evidence/fallback.json): 실제 재질 요청을 차단하고 같은 검사를 통과했다. 페이지 오류는 없으며 기존 육면체에서 가져온 기본 톤으로 표시한다.
- 기존 육면체 원본 6장 해시는 그대로이고, 동일한 자세와 시간으로 재생한 육면체 캔버스 픽셀도 이전 버전과 일치한다.
- [표면 계약](evidence/material-contracts.json): 실제 이미지가 전체 512×512로 로드되며 44개 면의 좌표와 기본 스킨 대체 동작을 확인했다. 렌더 준비에 난수 호출은 추가하지 않는다.
- [기존 주사위 손실 회귀](evidence/dice-loss.log): 손패 보존, 중복 차감 차단, 보상 대기열 유지·소비 및 두 보스의 개별 보상을 확인했다. [빌드](evidence/build.log), JavaScript 구문 검사와 diff 검사도 통과했다.

[렌더 비용 측정](evidence/render-performance.json)은 Chrome에서 슬롯과 중앙 주사위를 한 쌍씩 그렸다. D1 쌍의 Canvas 제출 시간 p95는 데스크톱 3.2ms, 휴대폰 화면 에뮬레이션 2.8ms였고 캐시 6.47MiB가 유지됐다. 이는 실제 휴대폰 하드웨어나 GPU 완료 시간 측정은 아니다.
