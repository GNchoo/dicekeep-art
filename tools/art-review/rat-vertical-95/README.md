# W1 쥐 정면·후면 가독성 조정

PR #31에서 쥐의 전체 크기를 줄인 뒤 정면·후면의 좁은 몸통이 휴대폰에서 너무 작게 보였다. W1 쥐의 정면·후면만 가로와 세로를 각각 1.6배 확대했다. 현재 옆모습과 W6 멧돼지의 모든 방향은 그대로 유지한다. 게임 코드 버전은 `game.js?v=95`다.

확대는 실제 반환 프레임의 `assetId`와 `view`를 기준으로 공통 그리기 함수에서 적용한다. 발밑 기준점을 중심으로 같은 비율로 확대하므로 몸을 세로로 늘이는 변형은 없다. 걷기 계산용 `drawHeight`는 21을 유지해 코너에서 방향이 바뀌어도 위상이 재계산되어 튀지 않는다. 정지 이미지, 로딩 대체 이미지, 관전, 사망 잔상에도 같은 보정이 적용된다. 반복 웨이브와 정예 쥐도 같은 규칙을 사용한다.

휴대폰 440×956 화면에서 실제 PNG를 사용하는 걷기 8컷의 전경 크기를 측정했다. 정면은 약 7.49×14.07px에서 11.98×22.51px로, 후면은 약 6.95×14.07px에서 11.12×22.51px로 늘어난다. 측면은 28.07×12.57px로 유지되며 정면·후면의 전경 면적은 2.56배가 된다. 1.6배는 작은 화면의 가독성을 위한 조정값이다. W6의 방향별 면적 비율을 정확히 복제한 값이라는 뜻은 아니다.

[이전 실측](baseline/report.json)과 [수정 실측](after/report.json)은 실제 HTTP 게임 코드의 SHA-256, 네 방향의 8포즈, W1/W6 크기, 실제 이동, 기절, 반복 웨이브와 정예를 기록한다. [방향별 표시 검사](view-contracts.json)는 실제 원화의 걷기·정지·대체 이미지, 사망, 관전 및 방향 전환 위상을 확인한다. 해당 검사는 내부 함수에 접근하기 위해 테스트 브라우저에서만 코드를 계측한다. 원본 이미지와 전투 수치에는 변경이 없다.

[기존 런타임 검사](runtime-contracts.json)에서 101웨이브 전투 수치, 관전, 부관 비율, 로딩 대체 이미지 및 타워 탄도를 확인했다. JavaScript 구문 검사, `tools/build-www.mjs`, `git diff --check`도 통과했다.
