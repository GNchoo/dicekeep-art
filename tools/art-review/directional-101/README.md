# 인피니티 방향별 몬스터와 7~20성 타워

2026-09-09 후속 수정: [v102 보스 하향 발끝 검수](../boss-front-footwork-102/README.md). b040/b040-2/b090/b090-2/b100의 정면만 교체했으며, 아래 v93 출시 근거는 당시 원본의 기록이다.

제작 범위는 W1~101의 고유 몬스터 110종(기존 10종의 방향 확장, W11 이후 100종)과 7~20성 타워 14종이다. 일반 웨이브와 군주 101종에 W20~100의 부관 9종을 더한 수다. 각 몬스터는 오른쪽 측면·정면·후면을 별도 제작하고 왼쪽은 측면을 반사한다. 걷기·기어가기 8포즈와 비행·부유 4포즈를 실제 게임의 진행에 맞춰 선택한다.

[네 방향·프레임 미리보기](index.html)는 저장소에서 `python serve.py`를 실행한 뒤 `http://localhost:8137/tools/art-review/directional-101/`에서 연다. 10개 웨이브 구간, 네 방향, 일시정지와 포즈 슬라이더, 타워 14종을 제공한다. 실제 배포 PNG를 읽되 확대 크기와 재생 시간은 검수용이다. 모든 프레임의 알파 범위를 합친 고정 배율을 사용해 꼬리나 무기가 잘리지 않고 프레임마다 크기가 변하지 않게 했다.

## 움직임과 게임 연결

- 기존 지상 7종의 승인된 측면 리그는 보폭을 정확히 1.5배로 넓혔다. 게임 이동 속도는 유지하며 한 걸음의 주기는 길어진다. 기존 비행 2종의 측면 픽셀과 박자는 보존했다. W10 보스도 걷는다.
- 각도별 고정 발 기준점과 같은 신체의 좌우 다리 ID를 유지한다. 코너에서 새 방향을 고를 때 1.2배 방향 판정 여유를 두고 누적 이동 위상을 초기화하지 않는다. 감속·기절·경로 순환·화면 회전도 같은 누적 위상을 사용한다.
- 데스크톱의 상단 경로에서 W70 대마법사의 머리가 최대 22px 잘리던 문제를 실제 게임 검사로 발견했다. 큰 공중 캐릭터는 위쪽 여유 공간에 맞춰 표시 고도를 낮춘다. 원본 프레임의 고정 기준점으로 계산하므로 프레임마다 위치를 맞추지 않으며, 논리 이동·공격 판정·그림자는 그대로다.
- 사족은 네 다리, 절지동물은 선언된 6개 또는 8개 다리, 손 모양 생물은 엄지부터 새끼까지 정확히 다섯 지지점을 사용한다. 비행은 날개를 몸통 관절에서 움직이며, 뱀형은 연결한 몸 마디를 순서대로 굽힌다.
- 부관의 표시 높이는 군주의 70%이며 전투 판정 크기·체력·속도·방어력은 기존 로스터를 유지한다. 101 이후 무한 반복의 첫 보스 부관은 별도 `b010-2`를 만들지 않고 같은 테마의 승인된 `b010`을 70%로 공유한다.
- 방향별 시트는 현재 웨이브와 다음 두 웨이브를 필요할 때 받는다. 디코딩 이미지와 출력 캔버스 예약을 포함해 96 MiB, 동시 로딩 2개로 제한한다. 각 캐릭터의 64px 인라인 대체 이미지는 시작 화면 전에 준비하므로 시트 요청 실패나 메모리 부족 때도 같은 캐릭터가 표시된다.
- 관전 메시지의 선택적 숫자 필드로 외형과 위상을 전달한다. 기존 프로토콜 3과 `net.js?v=89`를 유지한다. 비행·부유 관전은 로컬과 같은 이동 시계를 사용하며, 일시적인 시트 실패는 성공 이후 누적 로드 횟수와 분리해 재시도한다.

7~20성은 기존 6성에 효과를 더하는 대신 [전용 건축 원화 14개](../star-towers-07-20/README.md)를 사용한다. 별빛·성운·천공·차원 네 테마로 4+4+4+2종을 묶어 생성했다. 주사위 명판은 표준 5눈이며 포구 섬광과 초기 탄환 표시를 실제 건물 포구에 맞췄다. 탄환의 논리 발사 위치·경로·피해는 유지한다.

## 제작과 재현

`production-catalog.json`과 `design-briefs.json`이 전체 캐릭터의 정체성·이동형·디자인을 정의한다. 기본 이미지 생성 도구로 여러 캐릭터의 전신 시안과 부품을 묶어 요청했으며, 문제가 있는 몸통·장비·뒷면만 부분 교정했다. 실제 원본, 프롬프트와 SHA256은 루트·`middle-waves`·`late-waves`의 생성 기록에 있다. 금액은 생성 도구가 제공하지 않으므로 추정하지 않는다. 미선택 원본과 시안은 제작 기록이며 완성된 걷기 시트로 집계하지 않는다.

최종 승격 목록과 실제 요청 수는 [release-builds.json](release-builds.json)에 기록한다. **110종, 330개 시점, 실제 런타임 PNG 660개, 인라인 대체 이미지 330개**를 모두 승격했다. 움직임은 2,304포즈이며 정지 기준 포즈 330개가 별도로 있다. `complete: true`와 `partial: false`를 동시에 만족한 기록만 110종 출시 검사다. 각 빌드의 설정·manifest·출력 PNG·원본·이동 검수 해시를 함께 확인하며, `evidence/builds/`에 최종 20개 빌드의 검수 JSON 80개를 보관한다. 생성 입력과 증거는 Git의 개행 변환으로 해시가 바뀌지 않도록 원래 바이트를 보존한다.

실제 이미지 생성 요청은 **164회(몬스터 159회, 타워 5회)**다. 여러 몬스터와 몸통·다리·날개를 한 시트에 묶고, 교정할 부위만 다시 생성했다. 미선택 결과와 교정도 호출 수에 포함하며, 실제 비용 금액이나 절감률은 확인할 수 없다. 런타임 PNG 합계는 120,192,051바이트, 초기 `directional-art.js`는 1,311,432바이트다. 모든 PNG를 시작할 때 받는 것은 아니며, 인라인 대체 이미지의 고정 디코딩 분량은 5,406,720바이트다.

저장소 웹 화면에서도 열 수 있는 [110종의 세 시점 GIF 목록](evidence/previews/README.md)을 제공한다. 이 GIF는 최종 런타임 PNG를 그대로 조립한 1.2초 검수 루프이며 게임 안의 이동 속도를 나타내지는 않는다.

```sh
node tools/build-directional-art.mjs --config=<승인된 리그 JSON> --out=gen/<출력>
node tools/check-directional-art.mjs gen/<출력> --require-ready
node tools/preview-directional-motion.mjs gen/<출력>
node tools/promote-directional-art.mjs gen/<출력>
node tools/audit-directional-release.mjs <명시한 최종 출력 폴더 전부>
```

`prepare-*`·`make-*` 도구는 제작 중 설정을 준비하며 시각 승인 전에는 `reviewApproved: false`다. 재현에는 `release-builds.json`에 연결된 최종 승인 설정을 직접 사용한다. 모든 시안 폴더를 검색해 자동으로 승격하는 방식은 사용하지 않는다.

게임 검증 명령과 범위는 [브라우저 검사 안내](../../e2e/README.md), 관절·위상·분할 계약은 [DIRECTIONAL-RIG.md](../../DIRECTIONAL-RIG.md)에 있다. 101웨이브의 모든 방향을 오래 관측하는 아트 검사는 종료 없는 무한 모드를 사용한다. 도전 모드는 101웨이브 스폰 완료 시 종료되는 기존 규칙과 전투 수치를 별도로 검사한다.

## 최종 실행 결과

[runtime-release.json](runtime-release.json)은 부분 검사나 화면 밖 입구 검사를 제외한 최종 기록이다. 데스크톱 1240×860과 휴대폰 440×956 각각에서 **101웨이브·110종·440방향·3,072개 프레임 선택**을 실제 게임 캔버스에서 확인했다. 모든 관측 방향의 전경 노출은 100%, 기절 시 위상 보존은 각각 110종, 아트 요청·페이지 오류는 0이었다. 각 화면의 캐시 최고치는 88.65625 MiB, 동시 로드는 2개였다.

대표 이동형 10종은 화면별 코너 40회·루프 10회·화면 회전 10회·기절 10회를 통과했다. 50% 감속의 측정 이동 비율은 데스크톱 0.4867~0.5116, 휴대폰 0.4887~0.5057이었다. 101개 웨이브의 기존 체력·크기·속도·보상·방어력 보존, 관전 외형과 부관 크기, 네트워크 차단 시 동일 캐릭터 대체 이미지도 통과했다. 비행·부유 시계 54조건, 반복 주기 보스 5경우와 일시 PNG 실패 후 복구도 확인했다.

타워는 실제 렌더·발사 각각 28/28을 통과했다. [앱 패키지 검사](evidence/www-package/validation.json)에서 방향 PNG 660장·타워 PNG 14장·주요 스크립트 7개 총 681파일이 원본과 일치했고, `/www/`의 데스크톱·휴대폰 실제 부팅과 W1 진행을 확인했다. 네이티브 휴대폰 기기의 Capacitor 실행을 확인한 것은 아니다.

[자동 검사 기록](evidence/checks/checks.json)은 방향 리그 25개, 시트 분할 13개, 기존 리그 4개, 출시 감사 자기검사 19개를 통과했다. [네트워크 회귀 90/90](evidence/www-package/net-regression.json)도 통과했다. 원본 파일과 캡처·JSON의 SHA256을 함께 보관하며 `node tools/art-review/directional-101/record-runtime-release.mjs`로 완료된 실행 증거만 다시 모을 수 있다. 메인 반영과 실제 배포 상태는 후속 PR의 병합 상태 및 배포 검증 댓글에서 확인한다.

[PR #30](https://github.com/GNchoo/dicekeep-art/pull/30)은 메인 커밋 `8f325ea02c1f295262e1ce51e08f59d32b93331b`로 병합됐고 Cloudflare 웹 배포가 성공했다. [운영 검증 기록](evidence/production/deployment.json)과 [상세 HTTP·렌더 결과](evidence/production/directional-production.json)는 실제 `https://dicekeep.cgn3731.workers.dev/`에서 코드5개·PNG674개(122,424,331바이트)의 원본 일치, 데스크톱·휴대폰 각각110종/330fallback 부팅, W1/70/100/101의6정체성×4방향×2화면 총48개 렌더 검사, 7/20성 타워의 실제 표시를 확인한다. 샘플 전경 노출100%, 새 아트·페이지 오류0이었다. 운영 서버의 `/index.html`→`/` 정규화도 처리하며 HTTP 응답을 로컬 코드로 대체하지 않는다. 별도 `dicekeep-net` 빌드는 이전 main부터 실패 상태였으며 이 변경에서 서버 구현은 수정하지 않았다.

## 시각 검수의 범위

다리의 접지 위치·관절 길이와 몸통 종횡비를 고정하며, 털·장비·무기·날개의 앞뒤 방향을 원본과 최종 시트에서 확인했다. 고어, 상처나 부패 묘사 대신 온전한 갑옷·의상·털·껍질로 만든 판타지 게임 캐릭터를 사용한다.

이 아트는 부품을 연결한 2D 애니메이션이다. 갑옷 상체·망토·일부 장비는 고정되어 있고 확대하면 부품 질감의 이음이 보일 수 있다. 8포즈를 유지하는 동안 발 위치에는 최대 한 프레임 분량의 양자화가 남는다. 발 텍스처 근접 검사만으로 해부학적 정체성이나 가림을 증명하지 않으므로 각 방향의 실제 보드와 움직이는 검수 GIF도 함께 판정했다. 관전에는 서버 요약 전달 간격과 전송 거리의 정수 반올림으로 작은 지연·위상 보정이 남는다.

200마리 압박 검사는 일반 진행과 달리 110종과 모든 보스를 동시에 배치했다. 440개 종·방향 조합과 248,400회의 그리기를 관측했고 전경은 모두 화면 안에 표시됐다. 캐시 최고치는 95.90625 MiB, 동시 로드는 2개였으며, 제거 후에는 5.15625 MiB의 인라인 대체 이미지만 남았다. 이 조건에서 애니메이션 시트 809회, 방향별 정지 PNG 177,815회, 인라인 정지 대체 이미지 69,776회가 그려졌으며, 두 개 이상의 시트 포즈를 관측한 조합은 15/440이었다. 따라서 이 검사는 200마리 전부의 동시 걷기를 보장하지 않는다. 메모리 수치는 이 아트 캐시의 디코딩 이미지·캔버스 예약이며 전체 브라우저 RAM은 아니다.
