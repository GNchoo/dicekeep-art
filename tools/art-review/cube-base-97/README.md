# 육면체 기본 주사위 재제작

기존 육면체는 배경을 잘라낸 주사위 사진을 3D 면에 다시 붙였다. 사진 자체의 사선·주변 면·조명이 남아 있었으며, 3눈 면은 1눈 사진에서 눈을 복사해 만들었다. 새 기본 육면체는 v96 다면체와 같은 상아색 돌 재질 위에 정확한 눈을 합성한다.

## 적용 방식

- 공통 [재질 PNG](../../../dice/skins/ivory-worn/material.png)를 그대로 재사용한다. 이번 수정의 추가 이미지 생성 요청은 **0회**다. 원본 제작 기록과 프롬프트는 [v96 기록](../dice-base-96/README.md)에 있다.
- 192×192 평면 텍스처 6장을 만들고 실제 큐브의 `face.val`에 연결한다. 눈은 같은 간격의 3×3 좌표에 놓인 버건디색 음각 원이다. 사진에 들어 있던 원근·배경·다른 면은 사용하지 않는다.
- 바깥 사각 면을 먼저 클립한 뒤 내부 삼각형의 클립 경계를 0.6px 겹친다. 눈을 가로지르던 대각선 틈을 없애면서 인접한 면으로 재질이 새어 나오지 않게 한다.
- 1·2·3·4·5·6개의 표준 눈 배치와 반대면 합 7을 유지한다. 면 정의, 회전·정착 수학, 보상·확률은 변경하지 않았다.
- 슬롯, 중앙 굴림과 획득 여운, 물리 주사위가 같은 면을 사용한다. 손패·정보·드래그·상점의 작은 주사위와 타워·발사체 대체 그림도 같은 3D 큐브에서 만든다.
- 빠져 있던 `thumbURL` 함수를 복원했다. 썸네일 생성 실패로 옛 PNG가 재등장하던 경로와 옛 여섯 PNG의 런타임 요청을 제거했다.
- 재질을 불러오지 못하면 상아색 바탕과 동일한 눈 배치로 표시한다. 예전 사진으로 돌아가지 않는다.
- `content.js`의 외형 카탈로그는 모든 모양이 공유하는 재질과 표식 색을 기록한다. 상점 판매·스킨 소유권·장착 기능은 후속 작업이다.

게임과 콘텐츠 스크립트는 `v97`이다. 공통 PNG는 변경하지 않았으므로 재질 버전은 `96`을 유지한다.

## 검증 기록

실제 HTTP 게임 코드와 렌더 결과를 사용하는 브라우저 검증은 `gen/cube-refresh-check.cjs`와 `gen/cube-refresh-capture.cjs`로 실행한다. 휴대폰 화면 에뮬레이션은 440×956, 데스크톱은 1240×860이다. 원본 실행 출력은 `gen/e2e/cube-refresh/`에 보관한다.

기존 회전 회귀 검사는 다음 명령으로 실행한다.

```sh
node tools/dice-rotation-test.cjs
```

1,281개 회전 입력이 통과했으며 최대 목표 행렬 오차는 약 1.45×10⁻¹⁵다. 주사위 손실·중복 차감·보상 대기열 회귀와 앱 자산 빌드도 통과했다. 최종 브라우저 검증 결과와 실제 화면은 같은 폴더의 evidence에 보관한다.

[같은 자세의 수정 전·후](evidence/before-and-after.png) · [육면체 6면](evidence/six-faces-phone.png) · [기본 9종](evidence/all-dice-phone.png) · [상점 화면](evidence/shop-phone.png)

- [정상 로드](evidence/browser.json): 두 화면에서 9종 × 2 = 18회 회전·고정 UV·정착, 육면체 6면 × 2 = 12개의 실제 눈 개수와 표준 배치, 반대면 합 7을 확인했다. 손패·드래그·정보·상점도 12개 결과별로 같은 새 아이콘을 사용했다. 이십면체의 1~20 결과도 통과했다.
- [재질 요청 실패](evidence/fallback.json): 실제 재질 요청을 차단하고 육면체 6면과 각 UI 아이콘을 확인했다. 예전 주사위 PNG 요청과 페이지 오류는 정상·실패 경로 모두 0이다.
- 다른 8종의 원본 면 픽셀과 투영 좌표는 16건 모두 보존됐다. 예전 보관 PNG와의 전체 바이트 비교는 14/16이 같았다. phone d12/d20의 차이는 같은 브라우저에서 v96과 수정본을 재생한 [별도 대조](evidence/other-dice-control.json)로 확인했다. 이 대조에서는 8종 전부 RGBA 차이가 0이었다. 보관 시점이 다른 PNG 전체의 바이트 동일성을 일반적으로 보장한다고 주장하지 않는다.

최종 게임 SHA-256: `6e8456c947c0901824f872fd3ec26c334170424443c0cb5beb08a40c9934cba5`. 별도 대조는 내부 삼각형 틈 수정 전의 코드 `e28221c…39f3`를 사용했으며, 이후 변경은 육면체 내부 클립에 한정됐다. 최종 정상·실패 경로 검증은 위 최종 SHA로 실행했다.
