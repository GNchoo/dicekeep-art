# 세 모드와 성장 보상

순수운빨은 기존 101웨이브의 뽑기 확률, 골드, 파워업, 전투 곡선을 그대로 사용한다. 계정 해금·강화·구매는 소환과 피해량에 영향을 주지 않는다. 기존 통합 기록은 `legacy`에 남기고 새 모드의 기록과 구분한다.

덱빌드는 해금한 1~20성 주사위 중 정확히 5종을 편성한다. 골드 뽑기는 편성한 각 주사위를 20%씩 선택하고, 실제 회전 결과와 배치 타워의 별 수가 일치한다. 계정 레벨은 Lv20까지 적용하며 피해 배수는 `1 + 0.08 × (레벨 - 1)`이다. 보스 보상과 확률 진화는 기존 규칙을 유지하고, 덱 밖 타워는 계정 피해 보너스를 받지 않는다.

극한은 덱과 성장을 사용하고 101웨이브에서 끝나지 않는다. 계정 레벨은 Lv200까지 적용한다. Lv20 이후 피해 배수에 `1.08^(레벨-20)`을 곱한다. 102~202웨이브는 새 몬스터 로스터를 사용하고, 203부터 이 로스터에 최대 3단계의 진화 장식을 붙여 순환한다. 숫자 오버플로를 피하기 위한 체력 배율 상한이 있으며, 모든 수학적 웨이브에서 난이도가 무한히 증가한다는 뜻은 아니다.

극한 싱글은 시간 제한이 없다. 극한 함께하기는 기존 방 운영 한도인 100분 안에서 웨이브 기록으로 경쟁한다. 사망 시에는 완료 웨이브, 시간 제한 종료·중도 이탈 시에는 마지막 보고한 도달 웨이브를 기록하는 기존 서버 규칙을 사용한다. 순수운빨 방과 극한 방은 생성·참가·빠른 매칭·재접속 단계에서 분리된다. 이 순위는 클라이언트 전투 보고를 사용하는 2~4인 친구방/빠른 매칭 결과이며, 부정행위를 검증한 글로벌 랭킹은 아니다.

## 무과금 성장

- 기본 1~6성은 Lv1로 해금되어 있다. 나머지는 성장 조각으로 확정 해금한다.
- 모든 투기장 모드에서 완료 5웨이브마다 조각 5개를 받는다. 시작만 한 웨이브는 보상에서 제외한다.
- 모드별 첫 10/25/50/75/100웨이브마다 10개 추가, 101 클리어 시 20개 추가.
- 기본 보상은 한 판 최대 500개이며, 입장료와 일일 횟수 제한은 없다.
- 첫 25웨이브 종료는 45개, 이후 같은 모드 25웨이브는 25개다.
- 첫 101 클리어는 170개, 이후 같은 모드 클리어는 120개다.
- 7성 해금은 80개, 이후 별당 40개씩 증가하여 20성 해금은 600개다.
- Lv1→2는 10개. Lv20까지 업그레이드 비용은 `10 + 5 × (현재 레벨 - 1)`이며 이후 비용이 더 증가한다.
- 과금 전용 주사위·피해 배수는 없다. 구매는 무료로 얻을 수 있는 같은 조각의 획득 시간을 줄인다.

예를 들어 600개 상품은 같은 모드 101웨이브를 이미 클리어한 유저의 재클리어 5회 보상과 같다. 이는 보상량 비교이며, 무과금 유저가 101웨이브를 쉽게 또는 확정적으로 깬다는 주장은 아니다. 소환 운·덱·조작에 따른 실제 난이도는 출시 후 플레이 지표로 조정해야 한다.

게스트 진행은 기기에 보관된다. 로그인한 계정의 성장·구매는 commerce Worker가 관리한다. 기존 로컬 저장을 서버에 업로드해 유료 원장으로 합산하지 않으며, 로그아웃하면 기존 게스트 진행으로 돌아간다. 종료 보상은 런 ID로 중복 지급을 막고, 계정 보상의 네트워크 실패는 다시 확인할 수 있다.

## 주사위 렌더 최적화

D1은 구면을 삼각형 수백 개로 매번 변환·클리핑하던 방식에서, 화면상의 구면 표면에 역회전 UV를 샘플링하는 방식으로 바꿨다. 동일 프레임의 중앙·슬롯은 같은 결과를 재사용한다. 눈의 3D 회전과 상아 재질은 유지한다. D6 중앙은 원래 6분할 메시를 버퍼에 그리고, 자세·재질이 정확히 같고 해상도가 충분한 작은 슬롯은 그 결과를 축소해서 재사용한다. 재사용할 중앙 버퍼가 없는 슬롯은 기존 3분할 경로를 사용한다. 트레이·정착 캐시를 포함해 full 버퍼 2장과 독립 슬롯 버퍼 1장까지만 보관한다.

전투 중 여러 처치와 배속 시뮬레이션이 요청하는 HUD 갱신은 한 화면 프레임당 한 번으로 합쳐 DOM 레이아웃 반복을 줄인다. 전투 판정·난수·소환 확률·굴림 시간은 성능을 위해 변경하지 않는다.

Chrome 440×956, DPR2, CPU 4배 제한에서 중앙+슬롯 한 쌍을 측정했다.

- D1 회전 p50: 24.5ms → 8.2ms; p95: 51.3ms → 10.3ms.
- D1 정착 p50: 24.1ms → 0.6ms.
- D6 최신 정착 p50/p95: 0.8/1.1ms.
- D6 회전의 같은 브라우저 교대 비교 p50/p95: 22.9/28.5ms → 19.6/25.1ms. 평균은 23.35ms → 20.00ms로 3.34ms(14.3%) 줄었다.

D6 비교는 다른 빌드·브라우저 작업을 끝낸 뒤 같은 자세·재질·크기에서 전후 순서를 번갈아 20회 준비, 60회 측정했다. 데스크톱 평균은 5.32ms → 5.34ms로 개선이 없었다. 기본·왕실·서리·잿불의 6정착면과 4회전 자세를 작은 슬롯에서 직접 검토했으며 눈과 모서리 가독성을 유지했다. 중앙 기하·UV·21눈은 변경하지 않았다.

이는 렌더 함수 벤치마크이며 전체 게임 FPS나 실제 저사양 휴대폰 측정값은 아니다. 모든 기기에서 지연이 전혀 없다고 보장하지 않는다.

초기 D1 측정은 `gen/e2e/dice-performance/before/report.json`, 변경 후는 `after-final/report.json`, 외형·정착·버퍼 확인은 `after-visual-final/`에 생성된다. 최종 D6 교대 표본·요약·비교 보드·실제 게임 캡처는 `d6-shared-final/`에 있다. 생성 결과는 git에 포함하지 않는다. 재현 도구는 `tools/e2e/dice-performance.cjs`이며 최종 D6의 고정 소스와 명령은 `docs/FINAL-VALIDATION.md`에 기록한다.

## 결제 출시 상태

웹 Toss Payments와 Android Google Play Billing 연동을 구성한다. 기본값은 결제 비활성화다. 서버가 상품 가격, 구매 상태, 계정, 토큰 중복을 검증한 뒤 지급한다. 웹 결제 결과 URL의 금액과 클라이언트 구매 성공 알림만으로는 지급하지 않는다.

상품 초안은 60개/1,100원, 600개/9,900원, 2,000개/33,000원과 외형 묶음 3종 각각 4,900원이다. Android 최종 가격은 Google Play의 상품 정보를 표시한다. 실제 가맹점·Google 로그인·Play Console 상품과 판매자 정보 설정, 테스트 구매 및 환불 검증을 완료하기 전에는 실판매 상태가 아니다. 설정 및 운영 제약은 `commerce/README.md`와 `docs/ANDROID-PAYMENTS.md`를 참고한다.

## 주사위·타워 스킨

왕실 상아, 서리 수정, 잿불 흑요석은 각각 D1/D4/D6/D8/D12/D20의 공통 재질과 1~20성 타워 20개를 제공한다. D1/D4/D6은 눈, 더 큰 다면체는 숫자를 유지한다. 총 60개 타워 그림은 단순히 6성에 이펙트를 더한 형태가 아니라 별 수마다 다른 원화를 사용한다.

스킨에는 전투 효과가 없다. 서버가 확인한 소유와 장착 상태는 무료 성장 저장과 별개이며, 미리보기는 소유권을 만들지 않는다. 소유권이 환불로 사라지거나 로그아웃하면 기본 외형으로 돌아간다. 일반적인 장착 변경은 런 사이에만 적용하고, 굴리는 도중 외형을 교체하지 않는다.

생성 비용을 줄이기 위해 재질 3종은 한 장, 테마별 타워 20개는 한 장씩 만들었다. 왕실 배경 보정 1회를 포함해 총 5회 내장 이미지 생성 요청을 사용했다. 생성 도구가 금액을 반환하지 않아 비용 절감액은 산출하지 않았다. 원본·프롬프트·분할 코드·SHA256·검토 보드는 `tools/art-review/premium-101/`에 보관한다.

부팅 시 프리미엄 스킨은 읽지 않는다. 선택한 팩의 재질 1개와 타워 20개만 지연 로드하며, 동시 디코드는 2개, 보관은 최대 2팩으로 제한한다. 주사위 재질 버퍼도 최대 2종(104개 텍스처)을 유지한다. 다운로드나 디코드에 실패하면 기본 외형을 유지하고 상점에 준비 실패를 표시한다.

## 극한 몬스터 아트

102~202의 일반 몬스터 91종과 보스·부관 20종은 총 111개 외형이다. 캐릭터마다 측면·정면·후면 몸체를 새로 만들고 기존에 검증한 걷기·비행 리그에 합성한다. 지상·기어가는 83개는 방향마다 8프레임, 비행·부유 28개는 4프레임이다. 걷는 다리를 원화 몸체에 중복으로 그리지 않으며, 모든 프레임의 발 위치·소켓·알파를 검사한다. 보스와 부관도 별도 ID를 사용한다.

게임은 현재·다음 웨이브에 필요한 그림만 요청한다. 방향별 이미지 캐시는 96MiB와 동시 요청 2개로 제한하고, 진화 표식 3단계×3방향은 작은 공통 버퍼를 재사용한다. 이미지를 내려받지 못했을 때는 같은 로스터의 인라인 대체 외형을 사용한다.

새 모습은 관전·시체·잔존 웨이브에도 이어진다. 기존 외형 코드 1~457을 유지하고 새 외형·진화 코드는 별도 영역을 사용한다. 200마리의 외형·보행 위상이 잘리지 않도록 관전 적 문자열 한도는 5,120자, 클라이언트 전송은 6,000바이트, 서버 수신은 6,144바이트로 맞췄다. 1초 관전 중계·4인 방·기존 소켓 속도 제한은 유지한다. 클라이언트와 net 서버는 protocol 4로 함께 배포해야 한다.
