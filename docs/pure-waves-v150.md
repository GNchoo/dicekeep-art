# 순수운빨 일반 라운드 재조정 — v150

2026-09-25 사용자 요청: 90웨이브까지 거의 확정적으로 진행한 뒤 보스에서만 실패하는 흐름을 바꾼다. 중반부터 처치가 밀려 적이 누적되는 패배를 만들고, 일반 라운드의 수량과 시간을 메운디 자료에 맞춰 조사한다.

## 조사한 근거와 한계

기존 확률표가 참조한 **메이플운빨디펜스 5.0 BETA7.2**를 조사했다. RE 등 다른 버전과 섞지 않는다.

- [배포 맵](https://drive.google.com/file/d/1vN43XxC50wxFsF1tVpFLmPPU30pRvVag/view)의 추출 CHK SHA-256: `61374601bf6b9ef2a55b087b1e990db097567f060ade938bb6a6325bb72b8b63`. [맵 아카이브](https://scmscx.com/map/rkc866GB)의 해시와 동일하며, 파일 102,279,249바이트, 트리거 7,388개다.
- 일반 타이머를 140으로 설정하는 트리거(6714 등), 일부 보스 전환의 320, 초기 준비 40이 읽힌다. 일반 생성 템플릿(6916~7012)은 카운터가 29일 때 4개 레인에 각각 한 마리를 생성한다. 카운트다운 9 이하에서 생성 카운터를 초기화하는 코드도 있다.
- **보호된 EUD 맵이다. 위 트리거는 파일상 비활성 표시이고, 실행 중 복원 코드와 생성 카운터의 정확한 주기를 검증하지 못했다.** 원본을 실행해 모든 라운드의 수를 계측한 결과가 아니다. 추출기와 원본은 배포하지 않는 `gen/balance-audit/`에 보관했다.
- [공개 공략의 1라운드 설명](https://canfactory.tistory.com/m/1033)에 79마리가 명시되어 있다. 이것은 2차 자료이며, 모든 일반 라운드가 79마리라는 직접 근거는 찾지 못했다. **이번의 전 일반 라운드 79마리는 그 수치를 확장해 적용한 참고값이다.**
- [BETA7.2 안내](https://exysoft.net/%EB%A9%94%EC%9A%B4%EB%94%94/)의 일반 2분 20초·보스 5분 20초는 맵의 읽을 수 있는 값과 일치한다. 원본 게임 엔진의 배속과 실제 벽시계까지 같다고 주장하지 않는다.

따라서 **원본의 모든 라운드를 정확히 복제했다는 표현은 사용하지 않는다.** 원본 런타임의 단계별 수량이 확인되면 수량/간격 표를 그 근거로 대체할 수 있다. 보스 등장 단계, 타워 능력, 골드 경제는 이 게임의 규칙이다.

## 적용 규칙

순수운빨 `clear`와 같은 규칙의 함께하기에 적용한다. 덱빌드·극한·대전·협동의 전투 수치는 유지한다.

| 항목 | v150 |
|---|---|
| 일반 라운드 | 매번 79마리, 첫 생성 0.45초부터 마지막 130초까지 균등 생성 |
| 다음 라운드 | 시작부터 게임 시간 140초 후, 남은 적이 있어도 진행. 빈 필드도 조기 종료하지 않음 |
| 마지막 10초 | 추가 생성 없이 정리·배치 시간. 별도의 6초 막간을 다시 더하지 않음 |
| 시간 단위 | 게임 시간. x1은 140초, x2는 70초, x4는 35초의 실제 시간(정상 프레임 진행 기준) |
| 일반 적 체력 | 기존 배율 × `min(24, 1.06^max(0, wave−10))`. 1~10은 유지, 이후 점진적으로 증가. 후반에 추가 배율은 24에서 제한 |
| 처치 보상 | 기존 해당 라운드의 총 처치 골드를 79마리에 정수 분배. 정예 가중치 반영, 반올림으로 초반 골드가 소실되지 않음 |
| 보스 | 기존 종류·10웨이브 주기·보상·320초 제한·처치 후 6초 막간 유지 |
| 필드 한계 | 생존 적 200 초과 시 가장 오래된 적 이탈·목숨 −1. 사망 처리된 적은 제외 |
| 최종 라운드 | 140초 이후에도 잔여 적이 있으면 클리어 보류. 시작부터 최대 320초까지 정리 가능. 전멸하면 완주, 제한을 넘기면 실패 |
| 멀티 서버 | 순수운빨 방만 최대 5시간. 다른 모드 100분 유지. 웹 `net.js` 버전 150으로 구형 규칙과 같은 방 입장 방지 |

0.45~130초 균등 분배와 체력 곡선은 이 게임의 조정이며 원본에서 정확히 추출한 소환 간격/체력 수치가 아니다. 주사위 등급 확률, 실제 물리 착지 결과, 강화 확률, 타워 피해·공격 속도는 바꾸지 않았다.

## 검증

- 모든 91개 일반 라운드의 실제 소환 큐 79개·타임스탬프·총 골드와 10개 보스·다른 모드 격리를 검사한다.
- 큐/필드가 비어도 140초 전에는 진행하지 않는다. 다음 라운드에 살아남은 적이 이어진다. 최종 잔여 적은 허위 클리어되지 않는다.
- 죽은 적을 한계선에 포함해 목숨을 잃던 버그, 종료한 프레임에 남은 소환과 보상을 계속 처리하던 버그를 재현 후 수정했다.
- `tools/e2e/pure-luck-clearrate.cjs`는 실제 브라우저 전투를 고정 난수로 실행한다. 실행 시작 시 소스를 고정하고 SHA-256을 기록하며, `--reference=0f191ad`로 v149를 동일 러너와 비교한다.
- `--realtime-input=1`은 보물상자 개봉 2.2초와 주사위 물리 굴림 중에도 전투를 진행한다. 배치/판단은 즉시이고, 위험 강화 확인창은 직접 함수 호출로 생략한다. x1만 측정하며 실제 플레이어 승률을 뜻하지 않는다.
- 난이도 비교 수치와 최종 검사 결과는 아래에 기록한다.

|---|---:|---:|

- 판별 완료 웨이브: v149 `101, 89, 89, 99, 89, 79, 99, 101`, v150 `59, 59, 43, 47, 68, 46, 89, 59`.
- v150을 16판까지 확장하면 중앙값 59, 범위 43~94, 물량 초과 패배 9판, 보스 시간 초과 7판이다. 10판에서 일반 적 누적으로 목숨을 잃었으며 최대 생존 적은 200이었다.
- **소수의 자동 플레이 결과이며 사람의 승률이 아니다.** 이 정책의 16판 중 완주가 없었다는 사실로 게임의 실제 완주율이 0%라고 추정하지 않는다. 배치·강화 판단, 게임 배속에 따라 결과가 달라진다.
- 실제 전투 엔진에서 91~101웨이브 고정 보드도 검증했다. 모든 타워 Lv3, 6눈 파워 Lv10 기준 `20★×3 + 19★×3 + 17★×9`는 목숨 20·최대 적 50기로 완주했다. `20★×1 + 19★×2 + 12★×12`도 목숨 20·최대 적 155기로 완주했으나 마지막 정리 시간은 12.55초만 남았다. 두 검사는 91웨이브의 빈 필드에서 시작한 가상 보드다. 그 보드의 실제 획득 확률이나 90웨이브 이전 잔여 적은 검증하지 않는다.
