# 2족 무릎 방향 수정 (2026-09-14, v110)

최종 103종(기존 51·극한 52)의 잘못된 무릎 방향을 수정하고 검증·승격을 완료했다. 상체와 타워 동작은 변경하지 않았다.

## 확인 결과

98종은 세 방향 모두, 기존 w002·w003·w005·w007·w009 다섯 종은 정면/후면만 고쳤다. 다섯 종의 정상 측면은 유지했다. 합계 304개 수정 뷰의 보행 2,432프레임, 정지컷/보행 시트 608파일과 64px 대체 이미지 304개를 재생성했다.

첫 감사는 측면 기준이라 카탈로그 `biped` 105종 중 100종의 뒤쪽 굽힘을 찾았다. 실제 그림을 확인하니 w075·w176은 닭 형태이며 드러난 hock의 뒤쪽 굽힘이 의도된 외형이므로 제외했다. 방향별 추가 검사에서 측면이 정상이던 다섯 종의 정면/후면도 뒤로 굽는 설정임을 확인해 함께 수정했다. 현재 감사는 세 방향을 모두 검사한다. 나머지 동물·비행·부유 리그에는 이 수정이 적용되지 않는다.

b100·b201의 기존 실제 측면 8프레임에서도 앞쪽을 바라보는 몸통에 비해 무릎이 뒤로 접히는 모습이 확인된다. v107 상체 필터가 만든 문제가 아니라 기존 시트 생성 리그의 문제다. v110은 원래 부위 그림을 같은 관절·보폭 조건으로 시트로 다시 생성했다. 상체 변형이나 타워 변경을 추가하지 않았다.

전체 빌드·관절·래스터 무결성·이동 검사와 승격을 완료했다. 측면 전후 프레임 2·6은 98종을 확인했고 대표 여섯 종은 세 방향 8프레임으로, 추가 다섯 종은 정면/후면 80포즈로 검수했다. 이는 2,432프레임을 전부 눈으로 검수했다는 뜻이 아니다. 최종 `npm run test:biped-knees`의 단위/관절 검사 26건·세 방향 감사·실제 게임 618방향 배치·서버 이미지 608개/fallback 304개 디코드가 통과했다. 웹 빌드는 2,243파일로 완료했다.

## 원인

`tools/rig-walk.mjs`의 `solveLeg`는 발이 고관절 아래에 있을 때 `bend: 1`이면 무릎을 전방축의 음수 방향으로 보낸다. 이 모듈 자체의 설정 검증도 +1을 뒤, -1을 앞으로 정의한다. `tools/lib/directional-rig.mjs`의 측면 전방축은 `[1, 0]`이다.

초기 일부 인간형은 기존 리그의 `bend: -1`을 쓰지만 이후 신규 부위 리그와 극한 리그는 대부분 `bend: 1`을 사용한다. 뼈 길이·접지·무릎 각도의 크기를 확인하던 자동 검사는 굽힘 방향의 부호를 검사하지 않아 이를 거르지 못했다.

`anatomy: "biped"`를 명시한 수정 리그에는 전방 굽힘 검사를 추가한다. 화면에 투영하기 전의 고관절–발목 선을 기준으로 무릎이 전방에 있는지 검사하므로 정면/후면의 겹쳐 보이는 각도로 방향을 추측하지 않는다. 뼈 길이·접지·위상 검사는 함께 유지한다.

`tools/audit-biped-knees.mjs --check`는 현재 배포가 선택한 리그의 세 방향을 검사한다. 설정상 `biped` family와 실제 인간형 해부 구조가 완전히 일치하지 않으므로 조류 예외를 별도로 기록한다. 수정 대상은 `tools/art-review/biped-knees-110/selection.json`과 `legacy-selection.json`, 재현 설정·검수·승격 절차는 해당 폴더의 `README.md`에 있다.

## b100과 b201 외형

- b100: 파멸의 군주.
- b201: 별왕관 총사령관. `legacyAssetId`와 `baseRigId`가 모두 b100이다.

별도 이미지 파일이고 장식/재질에 차이는 있지만, 왕관·갑옷·망토·지팡이의 기본 형태와 관절을 재사용해서 실루엣이 거의 같다. 완전히 다른 보스 외형으로 제작된 것은 아니다. 극한 카탈로그에도 원래 이름/디자인과 기존 리그 재사용이 기록되어 있다.

## 보존 범위와 검증

`tools/prepare-biped-knee-fix.mjs`는 기존 릴리스가 선택한 설정과 현재 v102 발끝 보정이 적용된 설정에서 98종을 모은다. `tools/prepare-legacy-biped-knee-fix.mjs`는 초기 다섯 종의 정면/후면을 준비한다. 바뀌는 값은 인간형 다리의 `bend: 1 → -1`, 해부 검사 분류, 수정 방향의 캐시 버전과 새 검수 상태다. 원화 SHA·부위 좌표·고관절 소켓·링크 길이·발끝 반전(`flipX`)·보폭·위상·피벗·크기는 그대로 비교한다.

특히 b040/b040-2/b090/b090-2/b100 및 극한 b141/b141-2/b191/b191-2/b201의 v102 정면 발끝 반전을 보존한다. 각 수정 방향의 `assetVersion`은 110을 사용해 과거의 정면 전용 v102 캐시가 선택되지 않게 한다.

`node tools/e2e/biped-knees-runtime.cjs`는 승격 후 실제 스폰·세 방향 배치·서버 이미지 SHA/디코드를 검사한다. 변경하지 않는 118종 전체와 초기 다섯 종의 측면을 main `5630cdd`와 대조해 메타데이터 및 이미지 718파일이 같은지 확인한다. w075·w176과 초기 다섯 측면의 보존을 별도로 검증했다. 그림의 자연스러움은 실제 프레임 시각 검수로 확인하고 자동 무릎 부호 검사와 구분한다.

최종 세 방향 감사는 인간형 전방 굽힘 103종/309뷰, 조류 hock 2종/6뷰이며 뒤쪽·혼합·미해결 인간형은 0이다. 런타임 결과는 `tools/art-review/biped-knees-110/runtime-check.json`에 보관했다. Chrome의 두 화면 크기 검사이며 실제 휴대폰 하드웨어 성능 검증은 아니다.
