# 대전·협동 밸런스 검증 — v116

조사·실행일: 2026-09-14. 실제 `game.js` 전투와 두 브라우저의 WebSocket 통신으로 진행한 작은 자동 운영 실험이다. 실제 이용자의 클리어율·PvP 승률 추정이나 덱 전수 순위가 아니다.

## 선택한 협동 규칙

공동 HP 20, 공동 목표 700처치, 일반 적 HP 배율 0.75, 보스 HP 배율 0.6을 선택했다. 500처치는 기본 덱도 목숨 손실 없이 약 5분 20초에 끝났고, 1,000처치와 HP 상향을 함께 적용한 후보는 준비한 무료 덱 네 판 모두 목표 절반 정도에서 실패했다. 기존 HP를 유지하며 목표만 700으로 늘린 후보는 환원 연구 변형과 추천 덱 모두 약 7분 30초에 클리어하면서 공동 HP 4~10이 남았다.

숫자는 Dicekeep 자체 설정이다. Random Dice 2의 처치 수·난이도·보상 값을 그대로 옮겼다고 설명하지 않는다.

## 최신 생산 코드 확인

선택한 700 / 0.75 / 0.6을 공유 `battle-rules.js`에 반영한 생산 코드와 새 서버 사본으로 실제 신규 기본 2시드를 먼저 확인했다. 시작 스냅샷의 소유/해금 레벨은 1~6뿐이고 모든 숙련은 0이었다. 환원 연구 변형의 성공 결과를 신규 기본 결과로 대신하지 않았다.

실제 신규 기본의 두 판은 모두 90·180·270·360·450초에 보스가 출현한 뒤 끝났다. 기본 무료 성장으로 목표에 도달할 수 있음을 확인했으며, 중간·최대 성장의 대표 판도 완료됐다. 실제 이용자의 난이도나 성장 단계 간 평균 격차를 확정할 표본은 아니다.

혼합 경제는 같은 판의 폰 추천보다 소환이 49 대 43회, 모사 복제가 13 대 0회로 많았다. 그러나 처치는 332 대 352, 최대 동시 적 수는 25 대 13으로 전선 유지가 약했고, 공동 목표를 16처치 남긴 채 실패했다. 경제 카드를 넣는 것만으로 동료에게 공격·SP 지원이 생기지 않는 현재 구조를 드러낸 사례다. 아군 보급을 쓰지 않은 자동 운영 한 판이므로 모든 경제 덱이 실패한다는 결론으로 사용하지 않는다.

## 운영 방식과 한계

- 브라우저 두 개의 실제 전투 함수를 사용하며 각 화면은 390×844, 휴대폰 3열 배치다. 데스크톱 협동 결과로 일반화하지 않는다.
- 전투 간격은 1/30초, 조작은 0.5초마다 실행한다. 첫 빈칸부터 배치하고 낮은 눈금부터 합성하며 새싹은 보존한다. 모사는 같은 눈금의 첫 주력/광역을 복제한다. 전용 재배치, 군집 개수 유지, 고독 주변 빈칸 확보 같은 전문 운영은 하지 않는다.
- 소환 연출은 기존 `finishSlot` 훅으로 바로 끝낸다. 표의 시간은 이 자동 운영의 전투 시간이며 실제 사람이 조작한 세션 길이가 아니다.
- 보고는 시뮬레이션 2초마다 서버까지 처리하고 다음 구간으로 넘어간다. 이로 인해 전송·공동 피해 반영이 2초 단위로 묶이는 편향이 있으며 실제 지연 환경과 같지 않다.
- 개인 보급관은 쿨다운마다 사용한다. 서버 45초 쿨다운을 임의로 우회하지 않기 위해 **아군 보급은 사용하지 않는다**. 따라서 아군 SP 전달을 활용한 협동의 최대 효율을 측정한 것이 아니다.
- 서버 보상 시간은 실제 서버 참여 시간을 따른다. 가속 전투 시간을 보상 시간으로 바꾸지 않으며, 이 러너의 보상 지급액으로 시간당 경제를 추정하지 않는다.
- 각 비교의 N은 1~2로 매우 작다. 일부 보고서에 Wilson 95% 구간을 같이 기록하지만 사람의 60~85% 클리어율이 달성되었다는 통계적 근거가 아니다.
- HTML 가로채기로 발생한 소켓 연결 오류와, 개발 중 두 창 사이 HTML 버전이 바뀌어 발생한 참가 거절은 실행 오류로 별도 보관했다. 클리어율의 실패 판에 포함하지 않았다. 이후 브라우저 전투 JS/CSS와 멀티 버전값을 고정했다.

현재 순수 지원 덱은 공유 보상만으로 경제 카드의 외부 기여가 생기는 구조가 아니다. 고정 아군 보급은 모든 덱이 쓸 수 있고, 경제 SP를 동료에게 전달하는 기능은 별도 검증이 필요하다. 그래서 최종 비교는 포격을 포함한 혼합 경제 구성을 사용한다.

## 재현과 근거

러너: `tools/e2e/battle-matrix.cjs`. `--ref`가 있으면 해당 git 전투 소스를 사용한다. `--test-port`는 결과 디렉터리에 서버 소스를 복사하고 독립 테스트 서버를 실행한 뒤 종료한다. 생산 코드 수정이나 배포를 하지 않는다.

```powershell
node tools/e2e/battle-matrix.cjs --ref=74165f4d6754fdbc325c492128b30a9c477a8a62 --tiers=free --cases=starter-rebate,phone-top --seeds=110003,220009 --goal=700 --normal-hp=.75 --boss-hp=.6 --test-port=8807 --out=gen/e2e/battle-matrix-candidate-700
node tools/e2e/battle-matrix.cjs --ref=74165f4d6754fdbc325c492128b30a9c477a8a62 --suite=duel --tiers=free --cases=duel-starter --seeds=110003,220009 --test-port=8808 --out=gen/e2e/battle-matrix-duel-free
node tools/e2e/battle-matrix.cjs --plan=final --test-port=8809 --out=gen/e2e/battle-matrix-production-700
```

원자료는 `gen/e2e/` 아래 다음 디렉터리의 `report.json`이다. 각 행에 시드·계정 스냅샷·최종 보드·눈금·SP·진행 표본·결과·벽시계 소요 시간을 남겼다.

- `battle-matrix-v115-baseline`: 500 기준의 완료 3판과 별도 실행 오류.
- `battle-matrix-candidate-1000`: 1000/1.0/0.8 후보 4판.
- `battle-matrix-candidate-700`: 700/0.75/0.6 후보 4판.
- `battle-matrix-duel-free`: 무료 PvP 2판.
- `battle-matrix-production-700`: 최신 생산 코드 최종 확인. 브라우저 소스와 서버 사본도 함께 저장한다.
