# 모션 품질 조사와 다음 제작 범위

2026-09-14. 이번 커밋에서 완료한 것은 보스의 외형/이동 분류 오류 수정이다. 전신 애니메이션·타워 공격 시트·투사체/명중 효과의 전면 교체는 아직 수행하지 않았다.

## 현재 딱딱하게 보이는 이유

- `tools/lib/directional-rig.mjs`의 보행은 다리 관절과 발 접지를 중심으로 만든다. 몸통은 단일 이미지이며 지지 자세에서 제한된 상하 이동만 한다. 머리·가슴·골반의 반대 회전, 팔·무기의 후행 동작이 없다. 비행도 날개 회전 중심이어서 몸통의 반응이 부족하다.
- `game.js`의 `paintTowerBody`는 발사 때 가로 +7%, 세로 -9% 압축과 발광을 적용한다. 현재 타워와 디자인이 다른 과거 공격 시트는 사용하지 않는다. 같은 외형으로 준비→발사→복귀하는 프레임이 필요하다.
- 공격 코드는 레이저·연쇄 번개·포탄·냉기 등을 이미 구분하지만, 고성 타워는 공통 섬광과 링의 색/크기 변형 비중이 크다. 무기 유형별 발사 자세, 투사체 실루엣, 명중 형태를 함께 설계해야 한다.

## 제작 순서

1. 지상 보스 1종, 비행 몬스터 1종, 포격/마법 타워 각 1종을 시범 제작한다. 기존 색·실루엣·크기를 유지하고 원본과 실제 게임 크기에서 비교한다.
2. 지상 보행은 발 접지에 골반 체중 이동, 가슴의 반대 회전, 머리 안정화, 팔/무기 후행을 결합한다. 비행은 날개 힘주기→몸통 상승→회복의 시차를 만든다. 타워는 건물 바닥을 고정하고 무기/마법 장치가 준비→발사→복귀한다.
3. 옆/앞/뒤 시점과 반복 시작/끝, 고정 카메라, 동일한 캐릭터 비율을 확인한다. 출력 프레임 수는 실제 게임 크기와 메모리 비용을 보고 결정한다. 생성 영상은 배경 제거, 프레임 추출, 동일 발밑/발사점 정렬, 시트 패킹을 거쳐야 한다.
4. 투사체는 탄환/포격/서리/번개/에너지 등 역할별로 실루엣·꼬리·충격 형태를 구분한다. 효과의 시간과 색은 코드로 조정할 수 있어 전부 AI로 생성할 필요는 없다. 피해 판정 시점과 명중 효과 시점을 맞춘다.
5. 걷기 루프의 발 미끄러짐, 무기/날개 형상 변화, 상체 변형, 방향 전환, 타워 외형 유지 여부를 영상으로 검수한 뒤 전체 로스터로 확대한다. 200마리와 15타워 전투에서 기존 캐시 예산 및 실제 휴대폰 발열을 확인한다.

## Higgsfield 비용과 연결 상태

공식 MCP는 기존 Higgsfield 계정의 플랜 크레딧을 사용한다. 별도 API 키 없이 OAuth로 연결한다. 일반 MCP 생성에는 웹의 무제한/무료 생성 혜택이 적용되지 않는다고 공식 도움말이 안내한다. 모델·해상도·길이에 따라 생성 비용이 달라진다.

현재 제공된 Higgsfield 잔액 도구를 호출했으나 `USER_NOT_LOGGED_IN`을 반환해 계정 플랜/잔액은 확인하지 못했다. 생성 작업, 유료 플랜 가입, 결제는 실행하지 않았다.

연결 후 읽기 전용 비용 견적으로 시범 제작 1건의 크레딧을 먼저 확인할 수 있다. 전체 예산에는 시점·동작 수뿐 아니라 일관성 문제로 인한 재생성도 포함해야 한다. 자연스러운 영상 생성이 곧바로 접지·투명 배경·루프가 완성된 게임 스프라이트를 보장하지는 않는다.
