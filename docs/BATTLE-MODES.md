기존 순수운빨·덱빌드의 101웨이브 클리어, 극한, 2~4인 기록 경쟁은 유지한다. 위 시범 모드는 함께하기의 모드 선택에서 입장한다. 입장권, 유료 이어하기, 구매 전용 지원을 추가하지 않는다. 같은 계정의 무료/유료 성장 자원은 기존 규칙을 따르며 시범 대전은 등급이 붙는 공정 규격전이 아니다.

## 난이도와 복구

일반 적 HP는 기존 덱 전투의 `구간 × 2` 체력 곡선에 0.75배, 보스는 `보스 순번 × 10` 곡선에 0.6배를 적용한다. 외형 로스터는 재사용하되 일반 구간이 보스 그림을 선택하지 않게 분리한다. 15초 구간마다 기존 방식의 소액 SP를 지급하고 보스 처치 보상도 유지한다. 이 숫자는 최초 시범 설정이며, 기존 101웨이브 덱 클리어율 측정과 다른 전투다.

방은 최대 100분 후 종료하고, 접속 단절은 3분 동안 같은 좌석의 복귀를 허용한다. 보드·SP·발사체·성장 스냅샷·보스 순번·송신 대기열·수신 효과 ID를 함께 저장한다. 재접속 시 서버의 HP와 목표를 우선하고 놓친 적 생성/보스를 따라잡는다.

서버는 발신 순번과 수신 이벤트 ID로 중복을 제거하고 영속 저장이 끝난 뒤 승인한다. 실제 전투는 기기에 있으므로 서버가 적 처치를 완전히 검증하는 부정행위 방지 시스템은 아니다. 따라서 계정의 보상 티켓을 발행하지 않고, 검증되지 않은 서버 결과로 상점 재화를 지급하지 않는다.

## 검증

- `npm run test:battle-persistence`: 기존 저장 마이그레이션, 새 모드 스냅샷, transport, 무보상 중복 정산.
- `npm run test:net`: 정원·매칭·HP·전송·공동 종료·재접속·중복·저장 순서.
- `NET=ws://127.0.0.1:8790 npm run test:battle-multi`: 별도의 `PORT=8790 TIMING=fast node net/test/dev-server.mjs`를 실행한 뒤 실제 두 브라우저로 검사한다. Windows PowerShell에서는 `$env:NET`, `$env:PORT`, `$env:TIMING`을 사용한다.
- UI·전투 연결 검사는 실제 5처치 전송, 보스 만료, 폰 새로고침, 공동 성공/실패를 포함한다. 500처치 경계 자체는 프로토콜 입력으로 검사하므로 이 테스트를 자연 플레이 클리어율로 해석하지 않는다.

추가 실제 전투 스모크(`tools/e2e/battle-balance.cjs`): 동일 paired seed 110003, 두 390×844 보드, 숙련 0·기본 클래스·개인 보급관, 아군 보급 미사용으로 기본 덱 `[1,2,3,4,16]`은 약 330초/502처치/공동 HP20, `[2,5,13,14,19]`는 약 325초/501처치/공동 HP20으로 종료했다. 강제 처치·SP 가산 없이 같은 자동 운영을 사용했다. 각 덱 한 경기의 진입 가능성 확인이며 승률 통계가 아니다. 시간은 5초 단위 서버 보고 해상도이며 같은 구간에 처리한 적 때문에 목표보다 1~2처치 많을 수 있다.

이 스모크에서 사거리 안에 적이 오지 않은 타워의 공격 대기 값이 −100초보다 작아져 자동 저장이 거절되는 문제를 찾았다. 전투 행동은 유지하고 저장 검증의 합법 음수 범위를 늘렸다. 실제 실패 저장 복원과 재전투를 통과했다. 수신 효과는 FIFO 기록이 아닌 서버에 아직 승인되지 않은 ID를 보존해 오래된 ACK 유실도 중복 적용하지 않는다.
