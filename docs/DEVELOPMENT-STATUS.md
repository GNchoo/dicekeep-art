# 모드 개발 진행

기준: GitHub main `55204fe`, 2026-09-13. 순서: 기준 고정 → 덱빌드/공통 성장 → 극한 싱글 → 극한 멀티 → 스테이지 → 통합 검증.

## 첫 변경 묶음

- main의 순수운빨 12웨이브 전투/소환 결과를 3개 시드·2개 화면의 고정 fixture로 보관했다. `npm run test:pure-main`으로 재현한다.
- 모드별 웨이브 선택 경계를 만들었다. 순수운빨 수치와 덱빌드 체력은 유지했다. 아직 근거 없이 체력을 다시 조정하지 않았다.
- 성장 모드 확률강화가 기존 성장 배율을 이어받는다. 큰 배율 하나만 적용해 반복 곱셈을 막는다. 성장 모드는 모든 별의 타워를 판매할 수 있다.
- 덱 화면에 역할·계정 레벨·덱빌드/극한 적용 레벨과 배율을 표시했다. 선택한 1성 소환에 꽝 문구를 사용하지 않는다.
- Lv20 이후 성장 비용을 완화하고 기존 투자 차액을 한 번 반환한다. 외형 + 소액 성장 상품과 구매 확인 화면은 `BUSINESS-MODEL.md`에 기록했다.

## 실제 게임 자동 전투 표본

고정 정책 봇이 실제 브라우저 전투를 구동했다. 각 2회이며 사람의 승률이나 모든 덱의 균형을 입증하지 않는다. 값은 마지막 완료 웨이브다.

| 모드 / 덱 | 레벨 | 두 표본 결과 |
|---|---:|---|
| 덱빌드 1·2·3·4·5 | 1 | 79 / 79 (보스 시간 초과) |
| 덱빌드 3·4·6·7·10 | 10 | 89 / 89 (보스 시간 초과) |
| 덱빌드 4·5·14·18·20 | 20 | 101 / 101 (클리어) |
| 덱빌드 16·17·18·19·20 | 20 | 101 / 101 (클리어) |
| 극한 4·5·14·18·20 | 20 | 140 / 140 |
| 극한 4·5·14·18·20 | 50 | 170 / 170 |

모든 표본에서 보관 타워 때문에 행동이 막힌 횟수는 0이었다. 다양한 덱의 선택 가치는 더 큰 표본과 손플레이가 필요하다. 원자료는 무시되는 `gen/development/growth-initial`과 `extreme-initial`, 재현 도구는 `tools/e2e/growth-balance.cjs`다.

## 검사 범위

성장 모듈 15, 상거래 서버 35, 멀티 서버 107, 외형 16 검사가 통과했다. 덱/모드 브라우저 검사는 휴대폰 46·데스크톱 46, 상거래 클라이언트는 VM+브라우저 12 검사가 통과했다. 구매 확인 창은 휴대폰·데스크톱 모두 취소/ESC 무주문·확인 시 1회 주문·화면 경계를 검증했다. 순수운빨 기준 메인·계정 무관성 84개 검사도 통과했다. 실제 청구와 실제 휴대폰 하드웨어 검증은 수행하지 않았다.

## 남은 단계

극한 이어하기, 장기 성장/보상 측정, 멀티 보드 복구와 결과 기준, 50개 스테이지 구조·보상·안내, 최종 회귀 검증을 이어간다. 기존 자산을 사용하며 새로운 그림 제작이나 결제 실서비스 활성화를 완료했다고 간주하지 않는다.
