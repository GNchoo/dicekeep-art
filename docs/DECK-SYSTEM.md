# 수집과 덱 전투 (v111)

> v111의 역사·저장 호환 기록이다. 현재 v112의 계정 성장·획득·각성·서포터는 [다이스 트리](DICE-TREE.md)를 기준으로 한다. 아래 무료 보급·클래스·제작은 새 계정에 적용되지 않는다. 종류별 기본 역할과 기존 전투 소환·합성 규칙은 이어진다.

2026-09-14. 기존의 1~20성 해금·레벨 강화 중심 덱을, 종류·클래스·눈금·전투 강화가 각각 다른 역할을 갖는 시스템으로 변경했다. 새 덱빌드·극한 싱글·극한 멀티에 적용한다. 순수운빨과 캠페인은 기존 규칙을 사용한다.

## 참조한 구조

[Random Dice 공식 소개](https://apps.apple.com/us/app/random-dice-defense/id1462877149)의 다섯 종류 덱과 소환·합성 흐름을 기준으로 삼았다. 종류별 능력, 중복 카드와 골드로 올리는 클래스, 수집 성장에 따른 치명타 피해, SP 전투 강화는 [Dice 위키](https://randomdice.wiki.gg/wiki/Dice)를 참고했다. 같은 눈금 대상을 복제하는 [Joker](https://randomdice.wiki.gg/wiki/Joker_Dice)와 시간 후 성장하는 [Growth](https://randomdice.wiki.gg/wiki/Growth_Dice)도 구분했다.

카드 이름·그림은 Dicekeep 자산을 사용한다. 20종 능력의 수치, 세 개의 무료 프리셋, 보급 확률·보장 횟수·성장 비용은 이 게임에 맞춘 초기 설정이며 원작의 최신 수치를 그대로 복제한 것은 아니다.

## 네 가지 성장 축

| 구분 | 의미 | 범위 |
|---|---|---|
| 종류 | 공격·지원·제어·운영 역할 | 20종 중 서로 다른 5종 편성 |
| 클래스 | 같은 카드와 수집 골드로 올리는 영구 성장 | 일반 1 / 희귀 3 / 영웅 5 / 전설 7부터 최대 20 |
| 눈금 | 전투에서 타워마다 쌓는 성장 | 1~7, 눈금에 비례한 공격속도 |
| 파워업 | SP로 올리는 종류별 전투 강화 | 1~5, 새 전투마다 초기화 |

클래스는 시작 클래스보다 한 단계 오를 때 기본 피해에 3%를 더한다. 전 카드의 클래스 상승 합계는 치명타 피해에 단계당 0.5%p를 더한다(150%부터 최대 250%). 치명타 확률은 10%로 고정한다. 희귀도나 카드 번호 자체에 지수 피해 배율은 없다.

## 편성과 전투

- 프리셋 세 개에 각각 다섯 종류를 저장한다. 편집 중인 덱과 실제 사용 중인 덱을 구분한다. 이미 편성한 카드를 다른 자리에 넣으면 두 자리가 교환된다.
- 소환은 덱의 각 종류가 20%이며 항상 1눈금이다. SP 비용은 30부터 매 소환 5씩 올라 최대 530이다. 무료 추가 소환은 보상 대기열을 사용한다.
- 같은 종류·같은 눈금 두 개를 합성하면 덱의 무작위 종류 하나가 되고 눈금이 1 오른다. 7눈금은 합성할 수 없다. 빈자리로 이동하거나 호환되는 타워 위로 옮겨 합성한다.
- 모사는 같은 눈금의 다른 종류로 자신만 바뀐다. 대상 타워는 그대로 남는다. 새싹은 전투 시간 28초 후 눈금이 오르고 덱의 무작위 종류로 바뀐다.
- 종류별 파워업 비용은 100 / 200 / 400 / 700 SP이며 피해·사거리가 증가한다. 확률강화 UI는 새 덱 전투에서 사용하지 않는다.
- 수집 골드·성장 조각과 전투 SP는 별도 자원이다. 덱·클래스·치명타 피해는 전투 시작 시 고정해 도중 계정 변화가 영향을 주지 않는다.
- 인접 효과는 가로 5열, 세로 3열의 실제 배치를 따른다. 같은 지원 효과는 가장 강한 하나를 적용한다.

## 무료 수집과 구매

처음에는 1~6번 카드, 수집 골드 600, 무료 보급 3개를 지급한다. 보급 하나는 카드 5장과 수집 골드 120이다. 카드별 희귀도 확률은 일반 55%, 희귀 30%, 영웅 12%, 전설 3%이며 같은 희귀도 내 종류는 동일 확률이다. 전설이 없는 보급을 19번 열었다면 20번째 보급에서 전설을 보장한다. 전설 획득 시 보장 카운트를 초기화한다. 신규 계정마다 생성한 난수 상태와 개봉 결과를 저장하며 재시도 시 다시 뽑지 않는다.

보급은 판매하지 않는다. 원하는 종류는 성장 조각 20개로 확정 제작할 수 있다. 일반/희귀/영웅/전설은 각각 8/4/2/1장이고, 처음 한 장은 소유권을 얻는 데 사용한다. 클래스 강화에는 중복 카드와 플레이 수집 골드가 모두 필요하다. 현재 클래스와 희귀도 시작 클래스의 차이를 p라 할 때 다음 단계 비용은 카드 `2+2p`장, 골드 `60+40p+10p²`다.

모든 투기장 모드의 정산에서 기존 성장 조각과 함께 수집 골드·무료 보급을 지급한다. 완료 웨이브 w의 보급은 `floor(min(w,200)/10)`개, 골드는 `8×min(w,500) + 40×새 마일스톤 수 + 5×기존 첫/재클리어 보너스`다. 순수운빨로도 수집할 수 있다. 같은 전투는 한 번만 지급한다. 상품 가격·무료/유료 잔액·환불 정책은 [비즈니스 모델](BUSINESS-MODEL.md)에 기록했다.

## 기존 진행 이전

해금한 카드와 덱, 기존 레벨·조각·기록·영수증·환불 부채를 보존한다. 이전 경제 v2 기준으로 한 카드의 강화에 소비한 조각을 S라 할 때, 수집 골드 `10S`와 해당 희귀도의 제작 수량 `× floor(S/20)`장으로 환산한다. 이를 해당 카드의 클래스에 먼저 적용하고 남은 골드·카드는 보존한다. `collection.version=1`과 이전 기록을 저장해 두 번 지급하지 않는다. 이전 경제 개편의 무료 조각 반환도 별도로 유지한다.

구버전 진행 중 전투는 시작 당시 스냅샷을 유지한다. 새 규칙은 `growthSnapshot.deckSystem=1`인 전투에만 적용한다. `face`는 종류 ID로 유지하고 `pips`, `deckPower`, 능력·상태 타이머를 별도로 저장한다. 새 극한 관전 패킷은 `ds:1`, 타워 `[자리, 종류, 1, 눈금]`이고 기존 패킷은 세 항목을 유지한다. 서버도 함께 업데이트해야 새 관전 패킷을 받는다.

## 초기 전투 측정

실제 브라우저 전투를 고정 시드 41073, 종류별 시작 클래스, 전투에서 번 SP만 사용하는 봇으로 측정했다. 비교하려는 카드의 소유권만 준비했다. 각 조합 한 표본이며 사람의 승률이나 성장 기간을 뜻하지 않는다. 시간은 배속 전 시뮬레이션 전투 시간이다.

## 재현

로컬 정적 서버를 8137 포트에서 실행한다. `E2E_BASE_URL`로 다른 주소를 지정할 수 있다.

- `npm run test:progression` — 이전·새 성장, 일회 환산·지급
- `npm run test:deck-rules` / `test:deck-combat` — 합성·복제·능력·파워·전투 저장
- `npm run test:deck-collection` — 실제 덱 UI·카드 제작·보급·프리셋, 두 화면
- `npm run test:game-modes` / `test:run-resume` — 모드 경계·정산·구/신규 이어하기
- `npm run test:pure-main` — 기존 순수운빨 데이터와 12웨이브 전투 fixture
- `npm run test:commerce` / `test:commerce-client` / `test:net` — 서버 권한·중복 처리·환불·관전
- `npm run test:extreme-multi` — 8788 로컬 개발 서버와 실제 세 브라우저의 눈금 관전·재접속
- `npm run measure:deck` — 위 여섯 조합의 전투 재현, `gen/e2e/deck-balance/`에 결과

브라우저 검사는 테스트 전용 훅으로 상태를 준비한다. 실제 전투 측정만 보상을 자연 획득하며, 기능 검사용 준비 상태를 밸런스 근거로 사용하지 않는다. 네이티브 휴대폰 성능·실결제는 이 검사에 포함되지 않는다.
